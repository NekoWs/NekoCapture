# 注释格式规范

> 约束 `src/` 三个项目（FrameCapture / GestureCore / GestureEditor）的全部 C# 注释。
> `tools/` 只受 §9 扫描与 §5 语言约束，不要求 XML 文档、不要求拆文件。
> 机器可检部分固化在 `.editorconfig` 与 `scripts/lint-comments.ps1`（已挂进 `scripts/guardrail.ps1`）。

---

## 1. 一句话原则

**注释只写"代码自己说不清的当下事实"。凡是"曾经怎样"和"哪一轮改的"，一律不进代码。**

注释是**给下一个读这段代码的人**看的契约说明书，不是给上一个改代码的人记的工时账。
判断一条注释的价值，只问一个问题：

> 删掉它之后，下一个人会不会**更容易写出错的代码**？

会 → 留。不会，只是让他知道"这里以前不是这样" → 删。

### 1.1 为什么本仓对此特别敏感

历史上多次出现注释与代码不一致并被当作缺陷记录：注释声称"由后续分支重新点亮"而没有任何分支点亮；
类注释写着"不做耗时操作"而代码里就在做；字段已删除而"仅剩注释提及"。根因不是注释太多，
而是注释承载了**会过期的信息**——代码改了，没人回头改注释，注释就从资产变成陷阱。
本规范的全部条款都在消除这一类过期载体。

## 2. 保留（必须写）

| 类别 | 说明 | 正例 |
|---|---|---|
| **不变量** | 任何时刻都必须成立、且违反后不报错只出错的条件 | `// 不变量：图像不大于视口时 pan 恒 (0,0)` |
| **坐标 / 单位约定** | 物理像素 vs 逻辑像素、虚拟桌面绝对坐标 vs 窗口相对坐标、厘秒 vs 毫秒 | `// 物理像素，虚拟桌面绝对坐标；null = 全屏主屏` |
| **非显然的取舍理由** | 为什么选 A 不选 B，且理由不在代码里 | `// 小图绝不放大填充：放大只会糊` |
| **失败分支存在的原因** | 看起来"多余"的 return / 兜底为何不能删 | `// 目标窗被遮挡或取帧失败时回退区域截图` |
| **决策表 / 状态机语义** | 哪个状态允许哪个副作用，谁是唯一入口 | `// 不变量护栏：只有真正起录才允许隐藏范围轮廓` |
| **native 互操作事实** | vtable 槽位、GUID 出处、SDK 头文件名、DPI 虚拟化坑 | `/// <summary>IUnknown::QueryInterface（vtable slot 0）。</summary>` |
| **线程 / 重入 / 生命周期** | 必须在 UI 线程、必须 Dispose、不得在钩子内耗时 | `// 钩子回调内禁止耗时操作：超时会被系统静默摘钩` |
| **隐私 / 安全边界** | 为什么这里刻意不记录、不联网、不落盘 | `// 逐键 trace 仅在 FC_TRACE_KEYS=1 时启用` |

**行尾注释只允许这四类内容**：单位、坐标约定、归属（谁负责释放/谁拥有生命周期）、坑（不能删的原因）。
其余一律提到方法或类型的文档块里。

## 3. 删除（禁止写）

| 类别 | 例（本仓真实原文） | 处置 |
|---|---|---|
| **变更叙述** | `// R162：去掉悬停上浮（Lift），与普通按钮一致只改底色带过渡` | 删。要留的只有当下结论：`// 悬停只改底色带过渡，不上浮` |
| **需求 / 测试编号** | `/// <summary>R157：本条手势的「截图后」…</summary>` | 删编号，保留语义（§9） |
| **复述代码** | `// T1 GIF 编码往返 + 调色板 RGB 序回归`（紧邻 `Chk("T1-gif-header", …)`） | 删。代码字符串已自带编号与名称 |
| **重复方法名的分隔线** | `// ---------------- 捕获 ----------------` 紧跟 `void Capture()` | 转 `#region`（§7），且名字不得只是下方方法名 |
| **翻译式文档** | `/// <summary>获取名称。</summary>` on `string Name` | 不写。宁缺毋滥（§4.4 豁免） |
| **工时账 / 轮次流水** | `// 本轮加了 X`、`// 2026-10-13 改为 Y` | 删。git log 是唯一历史载体 |
| **被注释掉的代码** | `// _anns.Clear();` | 删。需要历史用 git |
| **TODO 无主挂账** | `// TODO 以后处理` | 要么写清条件与去处并进 `TODO.md`，要么删 |

### 3.1 硬禁词（扫描器 FAIL）

注释中出现即护栏失败，必须改写：

```
此前  之前  原来  曾经  曾把  曾让  退役  已退役  弃用  已弃用
改为  修掉  教训  历史  历史 bug  历史缺陷  早期  当时  过去
```

以及任何形式的 `R###` / `T###` 编号与 git commit 短码（§9）。

### 3.2 歧义词（扫描器 WARN，人工判定）

```
旧  不再  回归  修复  坑  bug
```

这些词**可能**在陈述当下事实。两种写法都合法，但必须自己判一遍：

| 判定 | 例 | 说明 |
|---|---|---|
| 合法（当下契约） | `// 录制中不再重入捕获` | 描述此刻行为 |
| 违规（隐含曾有 X） | `// 不再在方法开头散落 if-return` | 读者不知道曾经散落过什么，且代码里已不存在 |
| 合法 | `// 关掉则点窗按矩形区域截图` | 描述另一档开关的行为 |
| 违规 | `// 旧 TapThresholdMs 退役，改用固定值` | 字段已不存在 |

改写手法：把"不再 X"改成"现在 Y"；把"旧 X 已退役"整句删掉。

## 4. 载体分工

### 4.1 `///` XML 文档 —— 跨文件契约

给**别人会读的东西**：类型、`public` / `internal` 成员、枚举及其成员、接口。
IDE 智能提示与文档生成读它，所以它描述**调用方需要知道的事实**：前置条件、取值范围、
返回值的语义与失败约定、副作用、线程要求、谁负责释放。

```csharp
/// <summary>
/// 以锚点缩放：锚点下的图像点在缩放前后保持不动。
/// 返回的 pan 已按视口边缘钳制，调用方无需再处理黑边。
/// </summary>
/// <param name="zoom0">缩放前的倍率，须为正数。</param>
/// <param name="cx">锚点的视口坐标（逻辑像素），非物理像素。</param>
/// <returns>新 (zoom, panX, panY)；zoom 已钳制到 <see cref="MinZoom"/>–<see cref="MaxZoom"/>。</returns>
public static (double Zoom, double PanX, double PanY) ZoomAt(...)
```

### 4.2 `//` 独立行 —— 实现内说理

给**读实现的人**：为什么这个分支在、为什么这个顺序不能换、这段数学在解什么方程。
写在被解释的代码**上方**，缩进与代码对齐。

### 4.3 `//` 行尾 —— 四类速查

只放 §2 末尾所列四类。单条不超过 40 个汉字，长则提到上方独立行。

```csharp
private byte[]? _scrollPrevB;   // 上一 tick 抓帧，用于「滚动已停稳」判定
private IntPtr _prevFg;         // 关闭编辑器后归还焦点的目标窗
```

### 4.4 覆盖范围与强制强度

- `public` / `internal` 的类型与成员：**必须有 `<summary>`**；有参数必须有 `<param>`；有返回值必须有 `<returns>`。
  由 `CS1591` + `CS1573` = **error** 在构建期强制。
- `private` / 局部函数：**不强制**。只在存在非显然语义时写，写则用 `///` 或 `//` 皆可。
- 显式接口实现、`override`：不重复基类文档，用 `<inheritdoc/>`。
- 编译器生成物（`obj/*.g.cs`、`AssemblyInfo.cs`）不参与强制。
- **宁缺毋滥优先于覆盖率**：若某成员加文档只会变成复述签名，写进 `.editorconfig` 的豁免而不是硬凑——
  但豁免是逐条的，不是按目录批量关的。

### 4.5 标签白名单

只用 `<summary>` `<param>` `<returns>` `<remarks>` `<exception>` `<inheritdoc/>` `<see cref="">` `<c>` `<b>` `<list>`。
`<b>` 只用于强调不变量与"唯一"这类不可违反的字眼。

## 5. 语言与术语

- **中文为主**，与 `README.txt` / `PROGRESS.md` / 用户可见文案一致。
- 代码符号（类名、方法名、字段、枚举值、配置键、环境变量）保持英文原样，用 `<c>` 或反引号包裹：
  `<c>CaptureController</c>`、`` `FC_TRACE_KEYS` ``。
- **不翻译**：Win32 / WGC / GDI / DPI / LZW / median-cut / cubic-out 等术语与 API 名。
- 中英文之间加半角空格；标点用全角中文标点；不用句号结尾的单行注释（段落式文档除外）。
- 允许口语化说理（"放大只会糊"），但不允许含糊（"处理一下"、"特殊逻辑"）。

---

## 6. 长度与折行

- 注释单行上限 **110 字符**（中日韩字符按 1 计），与 `.editorconfig` 的 `max_line_comment_length` 一致。
- 多行 `<summary>`：**一个语义句一行**，不按视觉宽度硬折。
- 段落之间用空 `///` 行分隔（不是空行、不是 `/// `）。
- 单行 `<summary>` 与多行 `<summary>` 二选一：能一句话说完就用单行 `/// <summary>…</summary>`。

---

## 7. 分节：`#region`

- 85 条装饰性分隔线（`// ---- / ---------- / ----------------`）**全部转为 `#region`**。
- **只允许一层**，不嵌套。
- region 名必须是**职责名**，不是下方方法名的重复：

  | 合法 | 非法 |
  |---|---|
  | `#region 坐标换算与命中测试` | `#region 捕获`（下方就叫 `Capture()`） |
  | `#region 入场 / 退场动效` | `#region 其他` |
  | `#region 磁盘护栏与停录` | `#region 私有方法` |

- 禁止 `#region 其他` / `#region 杂项`——它是分类失败的藏身处。
- 单文件超过 **700 行**即应拆 partial（见 §10），region 不是拆文件的替代品。

---

## 8. 追溯：零编号

- 代码注释中**禁止**出现 `R###`（需求轮次）与 `T###`（SelfTest 用例）编号。
- 测试可追溯性由 `Chk("T145-…", …)` 的**名称字符串本身**提供——它已经在代码里，注释再写一遍就是复述。
- 需求可追溯性由 `git log` / `git blame` 提供。
- 需要指向测试时，用符号引用而不是编号：`<see cref="SelfTest"/>` 或写明"见 SelfTest 的裁剪用例"。

---

## 9. 历史与教训的去向

| 内容 | 去处 |
|---|---|
| 护栏型教训（曾经错在哪 → 根因 → 现在靠什么不变量/断言防回归） | `DECISIONS.md`，一条一节 |
| 轮次流水、"某轮把 X 改成 Y" | 直接删，git log |
| 待办 | `TODO.md`（代码里不留无主 TODO） |
| 界面/交互审计结论 | `UIAUDIT.md` |

代码侧只留**结论**，`DECISIONS.md` 留**论证**。写代码注释时不要复述 `DECISIONS.md` 的条目——
一旦复述，两处就会分叉，而分叉的那一份就是新的谎言。

---

## 10. 文件结构

- 单文件 **700 行**为拆分阈值，目标每文件 ≤ 500 行、职责单一。
- 拆分用 `partial class`，文件名 `<类名>.<职责>.cs`（例：`SettingsWindow.Capture.cs`）。
- 拆分是**纯移动**：不改逻辑、不改可见性、不重排成员。
- 拆出的每个 partial 文件顶部用一行 `//` 说明本 partial 承载的职责。

---

## 11. 禁止项汇总（评审逐条对照）

1. 变更叙述与硬禁词（§3.1）。
2. `R###` / `T###` / commit 短码（§8）。
3. 复述签名的翻译式文档（§4.4）。
4. 被注释掉的代码。
5. 只重复相邻方法名的分隔线；`#region 其他`（§7）。
6. 注释与代码不一致——**改代码必须同批改注释**，注释承诺的行为必须有实现。
7. 用注释解释"怎么做"来替代把代码写清楚（复杂条件应抽成有名字的局部变量或方法）。
8. 把 `DECISIONS.md` / `PROGRESS.md` 的内容抄进代码注释（§9）。

## 12. 机器护栏

| 工具 | 作用 |
|---|---|
| `.editorconfig` | `CS1591`/`CS1573` = error；`max_line_comment_length = 110`；缩进与编码基线 |
| `scripts/lint-comments.ps1` | 扫注释：硬禁词 FAIL、歧义词 WARN、编号 FAIL、超长 FAIL；`#region 其他` FAIL |
| `scripts/guardrail.ps1` | 已把上表挂为第 0 关，注释不合规直接 FAIL，不进构建 |

**豁免机制**：确需保留（如 native 互操作里 SDK 原文含"deprecated"字样），在该行尾加
`// lint-comments:ignore <一句理由>`。豁免必须带理由，扫描器统计豁免数并在收口时报告——
只增不减即视为技术债增长。

## 13. 新增 / 修改代码 checklist

- [ ] 新写的注释里有没有硬禁词？（跑 `lint-comments.ps1`）
- [ ] 有没有写编号？（应为零）
- [ ] 新增 `public`/`internal` 成员有 `<summary>`，有参有返有 `<param>`/`<returns>`？
- [ ] 改动的代码，其上方注释还成立吗？
- [ ] 这次踩到的坑是不是护栏型教训？是 → 写 `DECISIONS.md`，代码里只留结论。
- [ ] 行尾注释是否属于四类之一？不属于 → 提到上方。
